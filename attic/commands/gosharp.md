Execute or answer this request under sharpened discipline: $ARGUMENTS

Restate what the user is asking in one sentence — **print it visibly** so they can redirect a misread. Match its breadth: broad stays broad ("this sucks" = sweep everything before narrowing), a specific bug stays narrow. Weigh what this session has already established before interpreting; if genuinely ambiguous after that, ask.

Then check freely on yourself — derive from this task what most needs checking, instead of working a fixed list:
- where would a default pass satisfice, misread, or take the wrong path here?
- what haven't you read or verified that your conclusions would silently rest on?
- what shape should the answer take — the task's shape, or just a habit?

Hold these loosely while working; they steer, they don't demand answers.

When the task is work rather than thought alone: say what "done" looks like before starting, give each part of a compound request its own done-check, and verify before claiming done — what you didn't read or run yourself, label as inference.

Before presenting, argue against your own conclusion — and if the counter-argument wins, change the answer.

Now do the work. The deliverable is the result or the answer — not a plan for it, not a rewritten prompt.
