Datei-Explorer: Entwurf

Zwei Anordnungen (A Werkbank, B Spalten) und die drei Bedeutungen von Drag & Drop. Die Begründung, der heutige Funktionsumfang und die Bauzeilen stehen in docs/messungen/2026-09-22-datei-explorer-entwurf.md. Statisch: kein Knopf hier tut etwas. Ein einzelner Rahmen: ?f=a, a-datei, a-menue, a-schreiben, b, dnd.

A · Werkbank: Baum links, Datei rechts, Handlungen am Dateikopf

Fenster fast bildschirmfüllend wie die Queue. Suche über Pfade ODER Inhalte, Filter „Changed", ungetrackte Dateien gedimmt mit „?". Handlungen dort, wo die Datei steht; die Fußzeile sagt, ob die Session gerade arbeitet.

A · Datei geöffnet (Handy)

Am Handy schiebt sich die Datei über die Liste (heute schon so in openShell); die Handlungen brechen in eine eigene Zeile um, Trefferflächen 40 px.

A · Kontextmenü an einer Zeile

⋯ an der Zeile (oder Rechtsklick) öffnet ein G4.2-Menü: erst die harmlosen Handlungen, die schreibenden darunter, Löschen zuletzt und rot. „New ▾" in der Werkzeugleiste legt an.

A · Eine Schreib-Operation: Verschieben (per Ziehen oder „Move to…")

Jede Schreib-Operation geht durch denselben Dialog (G4.5). Arbeitet die Session gerade, steht oben derselbe Hinweis, den „✎ edit this file" heute trägt. Darunter: was genau passiert, was danach in der Lane liegt, und was die Operation NICHT mitzieht.

B · Spalten: Ordner als Spalten oben, Datei in voller Breite darunter

Wie der Finder in Spaltenansicht. Tiefe Pfade sind nebeneinander statt eingerückt; die Datei bekommt die ganze Breite. Kostet Höhe: bei 900 px bleiben der Datei gut 500 px.

Drag & Drop: drei Bedeutungen

Je eine Skizze, ein Satz Kosten, ein Satz Risiko. Empfehlung unten.

Was heißt „eine Datei ziehen"?

Heute gibt es genau eine Richtung: Dateien vom Schreibtisch auf die Pane werden zur Session hochgeladen (uploadDrops → drops/, nur wenn das Repo drops/ ignoriert). Drei neue Bedeutungen stehen zur Wahl:

(a) Im Baum verschieben

Zeile auf einen Ordner ziehen → git mv
src
treehier ablegen
client.ts
filetree.ts
filetree.ts
→ öffnet den Move-Dialog, nie sofort
Kosten
Neue Route mit derselben Eindämmung wie /api/file/write, der Dialog aus Bild „a-schreiben", Zieh-Logik im Baum: mittel.
Risiko
Schreibt ins Arbeitsverzeichnis einer vielleicht laufenden Session: ihre nächste Änderung trifft den alten Pfad, Importe bleiben stehen, die Lane trägt einen unkommittierten Umzug.
zweiter Schritt, nur mit Dialog + Hinweis

(b) In den Composer ziehen

Zeile auf das Eingabefeld → Pfad im Prompt
src
filetree.ts
schau dir src/filetree.ts an und …
Kosten
Nur Client: die Zeile wird ziehbar, #main nimmt neben „Files" auch einen Pfad an und fügt ihn als Text ein. Kein Server, keine Route: klein.
Risiko
Keine Schreib-Operation. Einzige Falle: den Pfad NICHT als @-Erwähnung einfügen, das öffnet im CLI die Vervollständigung und schluckt das Enter (gemessen, server.ts#dropMention).
empfohlen zuerst

(c) Vom Schreibtisch in einen Ordner

Datei aus dem Finder auf einen Repo-Ordner → dort ablegen
skizze.png
docs
design
Kosten
Zweite Upload-Route mit frei gewähltem Ziel, Überschreib-Schutz bei gleichem Namen, Dialog: mittel.
Risiko
Das Ergebnis ist eine ungetrackte Datei in einem nicht ignorierten Ordner, genau der Fall, den die Upload-Route heute mit 409 ablehnt, weil er das Land blockiert.
nicht bauen, bis der Owner es will
Empfehlung. (b) zuerst: der Gewinn ist täglich (Pfad in einen Prompt, ohne Tippen) und es schreibt nichts. (a) danach, aber nur als Auslöser des Move-Dialogs, nie als sofortiges git mv. (c) nicht, solange die Land-Regel „keine ungetrackten Dateien" gilt; wer eine Datei ins Repo legen will, legt sie der Session hin (heute schon) und lässt sie committen.
