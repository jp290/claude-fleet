## Korrekturen an der Analyse

1. B1-Kostenbild: Merge/Repair/CleanReview starten im Lane-Worktree (`mergeJob` cwd=lane.cwd an beiden Call-Sites) — dort lädt claude den LANE-Render (~43 KB), nicht das MAIN-Regelbuch (~84,6 KB). Zahlen je Render sind Claims, Struktur ist Code.
2. B1-Workerzahl: `WORKER_ROUTES` schickt summary/commitMsg/enhance/digest per Default auf codex-exec; watchdog deaktiviert cleanReview/autoReview/analysis; „bis zu vier claude-Worker je Land" ist der konfliktbehaftete Sonderfall.
3. B1-Sonde: das Worker-Transcript wird in `summaryViaSession` im `finally` gelöscht — „das Transcript lesen" funktioniert nur während des Laufs (oder mit temporär ausgesetztem rm).
4. B3-Vorkommen: der Satz steht an drei Stellen (`buildProgramMainBrief` gefehlt) — ein Schnitt nur in den Succession-Buildern repariert die Founding nicht.
5. B3-Id: `programContent` trägt keine Id; der Schnitt muss sie in den Brief EINFÜGEN (und der Pin „no program id in founding brief" in `e2e/programs.ts` ist dann bewusst mitzuschreiben).
6. B4-Ergänzung: fleet-report POST („not a worker lane") ist eine neunte lane-klassifizierende 409.
7. B8-Verify: Footer-Checks sind Substring/Heading-Pins, nicht byte-ganz — der Schnitt ist billiger als angegeben; nötig ist ein neuer Check, kein Fixture-Umbau.
8. §5-Rang: K2 ist von „grösster Hebel je Land" auf „Sonde, Bau nur bei Treffer" zurückzustufen (Default-Env + saubere Rebase-Rate).
