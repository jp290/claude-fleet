# Start-Session im leeren Projektordner

**Messstand:** Baum `f4b913213df6b09a79a3a8ec7db23c999b4086bd`, Host am 25.09.2026. „Neu und leer“ meint einen vorhandenen Ordner ohne `.git`, Projektregeln, lokale Settings oder Vorgänger-Session. Dateigrößen sind `wc -c` auf Disk, keine geschätzten Prompt-Tokens. `0 B` bedeutet nur für diese Definition keine Datei/Zustellung. Ein Ordner direkt unter `/Users/owner` erbt zusätzlich dessen `AGENTS.md`; an einem anderen Ort muss der Ahnenpfad neu geprüft werden.

## Urteil und Kosten

Die Empfehlung ist eine eigene Gründungswahl „Idee/Start“, die vor dem Harness-Start allein die kurze AGENTS.md schreibt und ausdrücklich keine Packs oder Rollenkarte zustellt. Der größte verbliebene Posten ist der Host-Kontext: bei Claude 8.090 B globaler Regeltext plus 36.515 B Settings-Dateien auf Disk, bei Codex 4.699 B globale Regeln, 33.428 B Config und unter dem Home-Pfad weitere 8.082 B Ahnen-AGENTS.md. Settings-Bytes sind **nicht** automatisch Prompt-Bytes. Ohne Harness-Isolation kann eine frische Idee bereits Betriebsregeln, Hooks, Plugins und Modellvorgaben dieses Hosts erben. **Die Vorlage erreicht Claude so noch nicht:** Claude lädt `AGENTS.md` nicht automatisch (`AGENTS.md:8-14`, `~/.codex/AGENTS.md:7-8`); für dieselbe Leitplanke braucht Claude entweder einen kleinen `CLAUDE.md`-Verweis oder eine knappe Startzustellung. Diese Ausnahme von „sonst nichts mitgeben“ ist eine offene Owner-Entscheidung. `server.ts:272-302`, `server.ts:1413-1465`, `src/client.ts:7848-7857`, `server.ts:42930-42970`.

## Tatsächlicher Fleet-Pfad

`GF_ROLES` nennt `plain` „Session in einem Ordner“; `gfRoleLabel` gibt nur `orch` und `steward` ein Label. `gfStart` ruft für `plain` `startSession` auf, dessen Body `cwd` und gewählte Spawn-Optionen enthält. `spawnBody` fügt `packs` nur bei eingeschalteten Schaltern hinzu (`src/client.ts:7810-7816`, `:7848-7857`, `:7999-8028`, `:7208-7220`, `:7725-7733`). Die Open-Route ruft `deliverOrchestratorSpawnCard` nur bei Orchestrator-Label und `deliverFoundingPacks` nur bei nichtleerer Pack-Liste auf; fehlendes `packs` ist ausdrücklich „today's founding“, `packs: []` ausdrücklich keine Packs (`server.ts:31704-31721`, `:42930-42970`). Es gibt bei `plain` daher **0 B automatisch gesendeten Rollen-/Worker-/Pack-Brief**. Das sagt nichts über den eingebauten Systemprompt der beiden Harnesses.

`GET /api/founding-plan?repo=…&harness=…&mode=main` zeigt *mögliche* Pack-Anker, liefert sie aber nicht selbst. `foundingPlanOf` verlangt über `repoRootOf` Git und über `integrationHead` einen HEAD (`server.ts:31674-31700`, `:6316-6323`, `:41861-41882`). Für den definierten leeren Ordner ist deshalb kein Plan verfügbar; nach `git init` ohne Commit weiterhin kein HEAD. Die Route mit Lane-Self-Token wurde read-only versucht und antwortete `{"error":"unauthorized"}` / HTTP 401. Falls später in einem Repo Packs ausdrücklich eingeschaltet werden, sendet `deliverFoundingPacks` einen Anker-Block, „kein Quelltext“, und misst `deliveredBytes` erst nach der Sendung (`server.ts:32577-32632`).

## Kontext-Inventar am Host

„Abschalten“ meint eine Option **für genau diesen Spawn**, keine Änderung geteilter Home-Dateien. CLI-Hilfe und Code belegen die angebotenen Schalter; ob sie alle gewünschten Loader zugleich abschirmen, ist ohne Probestart offen. Hook-Skripte laufen erst am jeweiligen Ereignis, ihre Disk-Bytes sind keine Startprompt-Bytes.
