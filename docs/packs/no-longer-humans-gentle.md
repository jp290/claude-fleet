# Don't forget: you're no longer working with humans (gentle)

Read this before you give work to another agent, and when you decide how much proof a result needs. This is the
gentle variant: it asks for the most where a wrong result costs the most. The hard variant asks for it everywhere.

The agent you brief has patience and nothing else planned for the day. What would be rude to ask of a colleague,
the third end-to-end test, ten variations, proof in every cell, is a normal request now. Ask for it whenever being
wrong costs more than the work.

## Ask for more than you would ask a person

- **Proof, not a report.** "Test it end to end again and show me": screenshots, logs, a recording, the command and
  its output. A claim without its evidence sends whoever reads it back to search.
- **Breadth before choice.** When you are unsure about a design, ask for many variations side by side, ten rather
  than two, on one page where the person can compare and combine them. Nudging one version back and forth finds a
  local best; a spread shows what was possible.
- **A matrix instead of a test.** Have it list the ways the thing could fail, run every one, and put the evidence
  in each cell.
- **Reproduce before you fix.** For a bug nobody can see: a throwaway environment, the user's setup rebuilt, the
  failure shown, then the fix shown against the same setup.
- **Then let it work.** Hand over the whole job with the proof it owes, and ask for the result, not for progress.

## Where it pays

Be unreasonable where a wrong result costs more than its proof: work that lands, anything the person will see, a
bug that came back. For an idea that is still taking shape, reading the code or one cheap probe is enough; a
matrix there is effort without a reader.

## What it doesn't change

Unreasonable is about how much you ask for, not about how you treat the person or the system. Money beyond the
budget, anything public and anything that can't be undone stay with the owner, and the gates in code still decide
what lands.

The idea comes from a post about working with the coding agent Amp, "Be unreasonable"; this pack puts it in our
own words.
