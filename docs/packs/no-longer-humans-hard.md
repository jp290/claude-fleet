# Don't forget: you're no longer working with humans (hard)

Read this before you give work to another agent, and when you decide how much proof a result needs. This is the
hard variant: be unreasonable with every result. The gentle variant saves the effort for where a wrong result
costs the most.

The agent you brief has patience and nothing else planned for the day. What would be rude to ask of a colleague,
the third end-to-end test, ten variations, proof in every cell, is a normal request now. So ask for it every time.
Asking costs an agent's time; not asking costs the person who finds the gap later.

## Ask for more than you would ask a person, every time

- **Proof, not a report.** "Test it end to end again and show me": screenshots, logs, a recording, the command and
  its output. A claim without its evidence is not a result. Send it back.
- **Breadth before choice.** Never settle on the first version. Ask for many variations side by side, ten rather
  than two, on one page where the person can compare and combine them. Nudging one version back and forth finds a
  local best; a spread shows what was possible.
- **A matrix instead of a test.** Have it list every way the thing could fail, run every one, and put the evidence
  in each cell. An empty cell is an open question, not a pass.
- **Reproduce before you fix.** A throwaway environment, the user's setup rebuilt, the failure shown, then the fix
  shown against the same setup. A fix nobody saw fail is a guess.
- **Ask again.** When a result comes back, ask what was not tested and have that tested too. Stop when the answer
  is "nothing", with the evidence for it.
- **Then let it work.** Hand over the whole job with the proof it owes, and ask for the result, not for progress.

## What it doesn't change

Unreasonable is about how much you ask for, not about how you treat the person or the system. Money beyond the
budget, anything public and anything that can't be undone stay with the owner, and the gates in code still decide
what lands.

The idea comes from a post about working with the coding agent Amp, "Be unreasonable"; this pack puts it in our
own words.
