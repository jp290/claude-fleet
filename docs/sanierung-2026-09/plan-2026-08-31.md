## Die tragenden Randbedingungen

1. **e2e/pins.ts ist ein Quelltext-Linter** (per Design, Header pins.ts:15): ein Split ohne
   Pin-Umhängung im selben Commit ist unmöglich. Nach dem Split wird jedes Modul ein natürlicher
   bounded slice — Pins werden einfacher. Gefahr: „Ein-Datei-Universum"-Pins (Bauart
   pins.ts:4214) werden nach Moves VAKUUM-GRÜN — als Klasse beheben (W3), je Slice prüfen.
2. **Server-Module → top-level `server/`, NIE `src/`**: `src/` wird als Client gelesen von
   bundleStale (server.ts#BUNDLES-Umfeld), verify-proportion.ts#ruleFor,
   task-metadata.ts#processesForPath. `server.ts` bleibt Entry-Name (Stage-Sentinel
   e2e-stage.sh, 8 Wrapper, Dockerfile, watchdog.sh, state.sh-pgrep). Stage-Kopierlisten sind
   import-abgeleitet — Module fahren automatisch mit.
3. **Kein Split neben laufenden Lanes**: git sieht einen Split nicht als Rename; der
   Konflikt-Pfad stoppt für Owner-Review, und Confirm-Land re-verifiziert nicht → Split-Slices
   nur in stillgelegten Fenstern, nie per confirm gelandet.
4. **Kommentare**: ~55–65 % tragender Vertrag, ~30–40 % Messgeschichte, ~2–5 % nachweislich
   stale — Exkavation heißt klassifizieren + verschieben (Sammeldokument), nie pauschal löschen.
5. **Rulebook-Pins laufen NUR im Haupt-Checkout** (rulebook/ gitignored; RULE_RENDER/RULE_GREPS/
   RULE_PATHS skippen in Lanes) → jeder P3/P4-Slice endet mit `bun e2e/pins.ts` IM
   HAUPT-CHECKOUT nach dem Land.
6. **Modell-Ökonomie**: server.ts ≈ 1,7 MB ≈ 400–480k Tokens — nur claude-1M-Lanes halten EINE
   Kopie; sol/glm bekommen bounded Arbeit (Module, `git diff --color-moved=dimmed-zebra`,
   pins-Diff), nie die Volldatei. Slices deckeln bei ~2.000 bewegten Zeilen.

Prior Art: `docs/attic/simplification-plan-2026-07-28.md` lehnte den Split bei 7,1k Zeilen ab und
validierte „Ableitungen hinaus, niemals Zustand" an 6 Extraktionen. Bei 25,5k ist die Ökonomie
gekippt; die Disziplin gilt weiter (s. Phase 4 Slice 2).
