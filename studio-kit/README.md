# Studio-Kit v1 (2026-08-18)

The mechanical invariants for setting up a working-circle studio — only what has FAILED in
measurement and whose mitigation is a mechanical check. Product-shaped rules never live here.
Origin and adjudication: `docs/grok-studio-kit-2026-08-18.md`; trail evidence:
`docs/private-repo-e-worktrail-audit-2026-08-17.md`.

**Use:** the program's founding brief references this kit by version. The MAIN copies the
templates into the program repo at first commit and fills the per-program half (contract,
proof-medium choice, rubric items, gate exit criteria). Promoting a kit change = editing these
files + a version bump here; a running studio keeps the version it booted with unless the owner
migrates it.

Contents:
- `standing-rules-template.md` — the verbatim block every worker/reviewer brief must end with.
- `brief-template.md` — mandatory slots for any worker brief.
- `state-note-template.md` — the termination artifact at the turn cap.
- `evidence-pack-schema.md` — pack rules + fidelity checks (the guardian is a script, not an agent).
- `setup-health-checklist.md` — run by the MAIN after the first two worker cycles, before any gate.
- `decision-record-template.md` — opens with the proof-medium derivation slot.
- `lessons.md` — the cross-studio delta ledger (size-capped, human-promoted, applicability
  predicates mandatory).

Permanent constraints all entries assume: one dev machine · finite context windows · nothing
auto-binds (a human promotes) · producers never write the anchor they are measured against.
